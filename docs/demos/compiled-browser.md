# Compiled browser demos

BANG can emit real WebAssembly 3.0 modules. The
[compiled demo pack](https://phibkro.github.io/bang/demos/compiled/) runs five fixed artifacts locally
in your browser—no Lean toolchain, compiler service, or server-side execution involved.

The pack includes:

- the multi-module JSON parser and calculator;
- N-Queens at sizes 4, 5, and 6; and
- the sim-KV program under two realizations, showing that the semantic description stays fixed while
  swapping the handler changes the result.

Each artifact is generated by `bang emit` and `wasm-tools parse`. The committed manifest pins the exact
compiler commit and version, every transitive BANG input hash, the resulting Wasm hash, and the expected
stdout bytes. Repository verification runs those bytes through Node and compares them with a live kernel
oracle. The production-site gate then opens the deployed page in Chromium and requires every selection
to report the same byte-exact match.

## The demonstrated boundary

The browser provides exactly one host operation:
`wasi_snapshot_preview1.fd_write` on stdout descriptor 1. The runtime rejects any other import or file
descriptor. That is enough for these emitted modules to show their result, and deliberately nothing
more.

This evidence means: **these committed modules execute on the enrolled engines and match their
repository oracles**. It does not mean:

- arbitrary BANG source is compiled in the browser;
- ambient filesystem, network, clock, randomness, or process authority is available;
- every browser implements the WasmGC and exception-handling features these modules use;
- the artifact is independently type-validated, cache-safe, or link-ready; or
- a finite differential corpus proves the compiler correct for every program.

Unsupported Wasm features, missing artifacts, unexpected imports, traps, and output mismatches remain
visible refusals/errors. The xv6 slice stays deferred until BANG has a real host-I/O authority and FFI
contract; this page does not stub that boundary green.

## Reproducing the pack

From a built checkout with `wasm-tools` available (directly or through Nix):

```sh
lake build bang
node tools/build-compiled-browser-demo.mjs
just test-compiled-browser-demo
```

The generator refuses dirty compiler or example inputs, compares every source program with the live
kernel oracle, and rewrites the artifact manifest deterministically. `just site-build` exercises the
same committed pack through the deployed `/bang` base path and a real headless Chromium instance.
