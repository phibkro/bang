The docs can't lie.
They're generated from the proof.

bang is a programming language with a formally-verified core, compiled to WebAssembly. Its reference isn't written — it's generated from the same verified source the compiler runs, and every example in it is machine-checked on every build. The documentation literally cannot drift from the language.

  • Verified core, honest edges. A small kernel — thunks, effects, handlers, STM — is proven correct in Lean; the rest is a tested superset, and the seam between them is marked, never hidden.
  • Paradigms are values. Imperative, transactional, reactive — each is a library over one kernel, installed as a handler you can swap.
  • Built to be generated into. Illegal states are unrepresentable, not linted — which is what makes it a safe target for an AI to write. bang itself is built by agent teams.

What's proven, and what's tested

The seam is drawn in the types, not blurred by a slogan.

Verified — proven in Lean, axiom-clean
  • kernel semantics
  • effect-row algebra
  • the CalcVM derivation
  • safety of the total fragment
the effect row — the marked descent
Tested — differential-tested vs the reference
  • the surface parser + elaborator
  • the runtime
  • the Div fragment (fuel-bounded)

Descent from verified to tested is never silent. A language that tells you precisely where the proof stops is more trustworthy than one that says "verified" and means "we have some tests."

v0.x — not production-ready, moving fast. Use it to explore the ideas, not to run your payroll.
