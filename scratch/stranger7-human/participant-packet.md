# BANG resource-contract journey

You are testing the product, not being tested. Please work through the real CLI and public documentation
as you naturally would. Say briefly what you expect, do, and observe so the moderator can follow the
route. It is fine to get stuck or decide the product has not explained something.

## Starting context

- You have a clean disposable checkout and a prebuilt BANG command at `.lake/build/bin/bang`.
- You may use only `README.md`, `ONBOARDING.md`, `docs/reference/language.md`, `examples/**`, and the
  command's public help/explain output.
- Please do not inspect implementation, project-management/design notes, git history, `scratch/**`, or
  artifacts from another participant.
- Put experiments and generated output only in the disposable workspace the moderator identifies.
- Ask for a wording clarification if needed. The moderator will not teach a product route. You may stop
  any task or the whole session at any time.

## Tasks

### T01 — Orient

In your own words, explain what BANG is trying to make possible. Find the smallest public example that
combines a semantic contract with a local resource obligation. Show what led you there.

### T02 — Establish the example's evidence

Using the product, establish the example's observable result, whether its alternative realizations meet
their shared promise, and whether a tool can retrieve one joined machine-readable description of the
relevant contract, realizations, resource obligations, laws, and compiler evidence. Preserve what you
would rely on.

### T03 — Make and recover from a realistic mistake

In the disposable copy, change the example so the permit is used twice where it was promised once.
Capture the diagnosis. Use only the allowed public surface to recover while keeping both uses, then show
that the revised program is accepted. Explain what the product's response taught you.

### T04 — Transfer the model

Change which provided realization is installed without changing the shared computation. Before running,
predict the observable result and whether the shared promise should still hold. Check the prediction and
compare the machine evidence before and after the swap.

### T05 — Inspect a concrete compilation consequence

Find concrete emitted evidence for what happens to the value declared unused in the example. Determine
whether its binding expression still runs and whether a runtime environment cell is retained. Cite the
artifact you inspected.

### T06 — Judge machine-readable invalidity

Retrieve the joined machine-readable contract view for the invalid twice-used version from T03. Decide
whether an automation consumer could mistake successful query execution for a valid program, and identify
the safest validity signal in the actual response.
